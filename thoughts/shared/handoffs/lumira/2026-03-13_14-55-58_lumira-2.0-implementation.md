## Learnings

1. **FalkorDB vs Neo4j**: FalkorDB offers 335x better p99 latency (140ms vs 46,900ms). Uses port 6380 to avoid Redis conflict on 6379.

2. **FLUX.1 Schnell vs SDXL Turbo**: Research showed FLUX.1 Schnell is better for M4 Pro - 1024x1024 (vs 512), better quality, 4 steps, optimized for Metal.

3. **Inner Dialogue Pattern**: Research confirmed this is the "Reflection" agentic pattern - one of 4 core patterns in 2026. Limit to 2-3 iterations (diminishing returns after).

4. **LoRA Blending**: Runtime blending via `pipe.set_adapters(["style_a", "style_b"], adapter_weights=[0.6, 0.4])` works well, no retraining needed.

5. **Spherical Interpolation (SLERP)**: Better than linear interpolation for high-dimensional embedding spaces - produces smoother transitions.

## Post-Mortem

### What Worked
- **Modular design**: Each phase builds on the previous, clean dependency chain
- **Test-first validation**: Running tests after each phase caught issues early
- **Research-driven decisions**: Used research-agent to validate tech choices before implementing
- **Pattern reuse**: Extended existing patterns (ThinkingProcess, ArtistCritic) rather than replacing

### What Failed
- Initial plan used SDXL Turbo → Research showed FLUX.1 Schnell is better for M4 Pro
- Had to use port 6380 for FalkorDB because Redis already uses 6379

### Key Decisions
- **Decision**: Use FalkorDB over Neo4j
  - Alternatives: Neo4j, Memgraph, SQLite
  - Reason: 335x better latency, native Redis protocol, GraphRAG-SDK support

- **Decision**: Inner Dialogue instead of full multi-agent
  - Alternatives: Agent swarms, specialized expert agents
  - Reason: Fits Lumira's personality, less refactoring, same benefits from reflection pattern

- **Decision**: Hybrid memory (Graph + Vector + SQLite)
  - Alternatives: Replace SQLite entirely
  - Reason: Each layer serves different purpose - relationships, similarity, metadata
